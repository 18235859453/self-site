# 在线文章后台方案

## 目标

在浏览器里创建和编辑文章、上传封面和插图、保存草稿并发布，免去手动创建目录、填写 Markdown 前置配置和执行 Git 命令。

## 推荐方案

使用托管 Pages CMS，通过 GitHub 登录并授权当前 self-site 仓库。站内增加“写文章”入口，跳转到托管后台。实际编辑界面位于 Pages CMS，不在博客域名内。保留 Hugo 和现有 GitHub Actions 部署。

另一个选择是自建嵌入式后台，能够定制站内编辑体验，但需要额外维护服务和登录授权。当前优先减少发布操作和维护成本。

## 功能范围

- 文章列表：浏览、创建、编辑现有中文文章。
- 编辑字段：标题、简介、日期、网址标识、分类、标签、封面、正文、草稿状态、目录和评论开关。
- 正文支持 Markdown 编辑；图片通过后台上传并插入文章。
- 新文章默认草稿，取消草稿状态并保存后进入现有自动部署流程。
- 草稿使用 Hugo 的 draft 字段，不出现在正式网站；这不是私密存储机制。

## 数据兼容

现有 content/post/<目录>/index.md 文章和图片保留原位置。配置时验证 Pages CMS 对嵌套文章目录、index.md 命名和图片路径的兼容性。英文 index.en.md 不作为新建中文文章的入口。新图片路径必须兼容网站的 /self-site/ 子路径。

## 发布与失败处理

后台保存文章到仓库默认分支，由已有工作流构建部署。保存成功与网站部署成功分开判断；保存失败保留编辑内容并提示，部署失败从 GitHub Actions 查看原因。不得宣称保存后立即上线。

## 授权与交付

用户在浏览器里完成 Pages CMS 的 GitHub 登录及仓库授权，不在源码中写入凭据。当前本机 gh 命令返回认证失败；实施中检查可用发布通道，上线时若仍无有效授权再完成用户登录。

交付包含后台配置、站内入口、简短使用说明和验证记录。

## 验证

检查配置和字段映射，运行 Hugo 构建，确认已有文章和图片正常。授权完成后，通过一篇草稿验证在线创建、编辑、图片上传与草稿不公开；公开发布测试需采用用户确认的内容，并验证部署结果。
